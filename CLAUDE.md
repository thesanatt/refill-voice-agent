# Prescription Refill Voice Agent

A voice agent for a pharmacy phone line. A patient calls, verifies their identity and requests a refill: they pick a medication, confirm the pharmacy, confirm their insurance and hear their copay. If the call drops before the request is complete, the conversation continues over SMS from the step where it stopped.

The original problem statement is `docs/TAKE_HOME.md` (verbatim). Clarifications from the kickoff call are in `docs/KICKOFF_NOTES.md`. Design decisions are logged in `docs/DECISIONS.md`.

## Scope

In scope:
- One demo patient (Sarah Chen) seeded in a real database, with prescriptions, a pharmacy, insurance and a copay table.
- A browser page that simulates the phone call (start and end the call, microphone in, agent audio out) and a chat view that simulates SMS.
- The full happy path by voice, and the SMS fallback from any point in the call.
- A completed refill request record holding every collected field.

Not yet: real telephony or SMS providers, authentication, multiple patients, recovery after a server restart, a polished UI and CI. The extensions in `docs/TAKE_HOME.md` start only after the core flow works end to end, several runs in a row.

## The flow

1. Greet the caller, ask for their full name and date of birth, and match both against the database. On a mismatch, ask once more for the date of birth. A second failure offers a pharmacist.
2. Medication: list the active prescriptions with each drug's purpose; the patient picks one or says it is not on the list.
3. Pharmacy: confirm the pharmacy on file, or record a different one.
4. Insurance: read back the plan and the last four digits of the member ID on file and confirm they are current.
5. Copay: look up plan plus medication and state the amount.
6. Read back a short summary with the price, ask to send it, create the refill request on yes and end the call.

## Conversation state

- Each step's result is written to the database as it happens: a session record holds the patient, the collected fields and the channel, and the current step is derived from the collected fields. Nothing collected lives only in the model's context.
- The state record, not the model, decides what has been collected. All reads and writes go through the tool layer, which enforces the gates. The model calls it, and so does the core.
- When a call ends before completion, the system sends a simulated SMS that says what is done and asks the next question, for example: "Looks like we got disconnected! I have your Lisinopril refill started. Which pharmacy would you like to use?" Before verification the text names no drug.
- The SMS conversation resumes from the derived step and never asks again for a field already collected. Unverified values do not count as collected.

## Quality bar

- Conversational speed: measure the time from the true end of the patient's speech at the microphone to the first audible agent content in the browser, log it for every turn by turn class, and keep it low (target: under about 1 second). A working phrase is logged as first sound and does not count as first content. Stream wherever possible.
- The agent stays on the workflow: short spoken sentences, one question at a time. Every medication, pharmacy, plan and price it says comes from a tool result, and sentences carrying these are rendered by code, never generated by the model.
- Spoken dates and names are normalized before lookup (for example, "March fifteenth, nineteen eighty-five"): the LLM maps speech to typed fields and code validates them, with an exact date match and a loose name match.
- Talk-over, early answers, questions back to the agent and data protection follow D6 in `docs/DECISIONS.md`. Working phrases follow D5.
- Runs locally on macOS and Windows with written setup steps. Secrets live in `.env`, which is never committed; `.env.example` lists the variables.

## How we work

- Architecture choices are made explicitly. The coding agent proposes two or three options with their tradeoffs, the engineer chooses, and the choice and the reason go into `docs/DECISIONS.md` before the code is written.
- Build in thin vertical slices: first a text-only agent loop with tools and database state, then voice, then the SMS fallback, then latency work.
- After each slice, run the happy path end to end, then commit with a clear message.
- Keep the code small and readable: clear names over comments, no dead code.
- Every session is logged from its first turn: a Stop hook exports the transcript to `agent-logs/` after each response (`.claude/hooks/export_transcript.py`). Commit the logs with the code.

## Repository

- The code lives in a private GitHub repository. If `git remote -v` is empty, create it with `gh repo create refill-voice-agent --private --source=. --push` (the `gh` CLI is logged in).
- Push after every working slice, so work can continue from a second machine (Windows). Keep scripts and setup steps cross-platform.
- The finished repository, with `agent-logs/`, is shared with the reviewers at submission.
